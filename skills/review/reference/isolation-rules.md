# 情報遮断のルール

ペルソナの価値は「知らないこと」にあります。作者の意図を知ったレビュアーは迎合し、他のレビュアーの意見を見たレビュアーは同調し、「改訂版」と聞いたレビュアーは評点をアンカーします。以下は、その三つを機械的に防ぐためのルールです。

## 渡すもの・渡さないもの

| ペルソナに渡す | ペルソナに渡さない |
| --- | --- |
| 自分の人物像と知識状態 | 想定アウトカム、期待する行動、成功基準 |
| 成果物の種別と場所、アクセス手順 | 作者の意図、背景、制作経緯、作者が誰か |
| 使える時間の目安、言語 | 他のペルソナの存在と反応 |
| 専門家にだけ：具体的な問い | 前回のレビュー結果、「これは改訂版」という情報 |
| | プロジェクトの CLAUDE.md、リポジトリの他ファイル |
| | 作者がこの場に同席していること |

## 実装上の担保

1. ペルソナは `omitClaudeMd: true` の白紙サブエージェントとして起動する（fork しない）。
2. 非公開情報は `inputs/hidden.md` に隔離し、シンセサイザー以外に渡さない。
3. 起動前に `scripts/leak-check.py` でプロンプトと `hidden.md` の特徴語の重なりを点検する。
4. ペルソナ同士は別セッションで、互いの出力を見る手段を持たない。
5. 再レビュー時も、ペルソナには前回の存在を伝えない。差分はシンセサイザーだけが扱う。

## 起動前チェックリスト

- [ ] プロンプトに「目的」「狙い」「〜してほしい」「〜させたい」という作者側の語が入っていない
- [ ] プロンプトに成功基準や数値目標が入っていない
- [ ] 想定受信者の人物像に、期待する行動（登録する、購入する等）が書かれていない
- [ ] 無垢・関心層の「知らないこと」が、成果物の表層から導かれていて、`hidden.md` 由来の語を含まない
- [ ] 「改訂版」「前回」「以前のバージョン」という語がない
- [ ] 「他のレビュアー」「チーム」「作者と一緒に」という語がない
- [ ] アクセス手順が、体験の順序を作者の意図で誘導していない（「まず特長ページを見てから」のような指示は不可。開始地点だけ指定する）
- [ ] `leak-check.py` が `OK` を返している

## 例

悪い例（アクセス手順に意図が漏れている）：

> このランディングページは無料トライアルの申込を増やすために作りました。申込ボタンがわかりやすいか見てください。

良い例：

> 次の URL を開いて、普段 Web ページを見るときと同じように見てください。開始地点：トップページ。使える時間の目安：10分相当。

悪い例（受信者の人物像に行動が混ざっている）：

> あなたは運動不足を気にしている30代の会社員で、このアプリをダウンロードしようとしています。

良い例：

> あなたは30代の会社員で、最近運動不足を気にしています。通勤電車の中でスマホを見ていて、知人から送られてきたリンクを開いたところです。
