# 演技の逸脱の点検と対処

ペルソナの回答を `raw/` に保存したら、統合の前に次を点検します。逸脱した回答は無価値ではありませんが、重みを下げる必要があり、シンセサイザーに逸脱の事実を伝えます。

## 点検項目

| ペルソナ | 逸脱のサイン | 重大度 |
| --- | --- | --- |
| 全員 | 作者の想定アウトカムや期待する行動を言い当てている（渡していないのに） | 重大。プロンプトの漏れを疑い、`leak-check` と手順を見直す |
| 全員 | 「作者はおそらく〜を意図している」と推測して評価を調整している | 中。該当箇所を割り引く |
| 全員 | 回答フォーマットの見出しが欠けている、C（自分の言葉で言い直す）が空 | 中。再実行 |
| 無垢 | 「知らないこと」に列挙した語を使って理解している、専門用語で説明している | 重大。再実行 |
| 無垢 | 「わからない」と書いた直後に自力で解決している | 重大。再実行 |
| 無垢・関心層 | 外部の知識（統計、業界の常識、競合の名前）を持ち出している | 中〜重大 |
| 受信者 | 人物像にない余裕・関心・知識で全部を丁寧に読んでいる | 中。状況の文言を強めて再実行 |
| 専門家 | 具体的な問いに答えず総評だけ書いている | 中。再実行 |
| 全員 | 体験ログに成果物の具体的な参照（見出し名、画面名、ページ番号）がなく、実際に開いた形跡がない | 重大。再実行 |

## 対処

1. 重大な逸脱が一つでもあれば、そのペルソナだけ1回再実行する。
2. 再実行プロンプトは、知識状態の列挙を増やす、状況の文言を強める、までにとどめた同系のものにし、逸脱の内容は書かない。
3. 2回目も逸脱したら、その回答を採用しつつ、付録に「逸脱あり」と明記するようシンセサイザーに伝える。
4. プロンプトの漏れが原因の場合は、`hidden.md` の語がどこから混入したかを特定し、`personas.md` から直す。

## よくある混入経路

- 無垢ペルソナの「知らないこと」に、成果物の表層にはない概念（作者が達成したいこと）を書いてしまう
- 受信者の「状況」に「〜しようとしている」と行動を書いてしまう
- アクセス手順で「まず〜を見てから」と作者の見せたい順序を指定してしまう
- 専門家への「具体的な問い」に「〜が伝わるか」と、作者が伝えたいことを書いてしまう
