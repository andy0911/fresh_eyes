# 論文のレビュー

## 受け付ける形式

- PDF（Read でページ指定して読める。変換不要）
- Markdown、テキスト
- LaTeX はコンパイル済み PDF を使う（ソースのままでは数式と図が読めない）
- Word（`scripts/to-markdown.sh` で Markdown 化し、図は PDF で参照）

## 準備手順

1. ページ数と構成（要旨、序論、方法、結果、考察、図表の数）を把握する。
2. 20ページを超える場合、ペルソナの時間目安を調整する。専門家は全読、関心層は要旨・序論・図表・結論、無垢は冒頭2ページ、受信者は受信場面に応じて（査読者なら全読、意思決定者なら要旨と結論）。
3. 図表が別ファイルなら `work/paper/` にまとめる。
4. 査読形式（匿名、採否判定あり）を想定する場合は、専門家に「採否の推薦とその理由」も求める。

## ペルソナに渡すアクセス手順（雛形）

```
1. 次のファイルを開いて読んでください：<絶対パス>（PDF の場合はページを指定して順に読めます）
2. 普段、この種の文書を読むときと同じ読み方で読んでください。全部読む必要はありません。
3. 使える時間の目安を過ぎたら、途中でも回答に移ってください。
```

## 専門家の既定プロファイル

| 既定 | 代替 |
| --- | --- |
| 同分野の査読経験がある研究者（論文の題材の表層から分野を具体化する） | 統計・方法論の専門家、分野外だが隣接領域の研究者、学術出版の編集者、英文校正者 |

統計や方法論が重要な論文では、「同分野の査読者」と「方法論の専門家」を別ペルソナとして立てることを推奨する（`--personas` で追加）。

### 専門家への具体的な問い

1. 要旨で主張されていることは、本文の結果で裏付けられているか。裏付けの弱い主張はどれか。
2. 新規性の主張は、先行研究との比較で成り立っているか。欠けている比較対象はあるか。
3. 方法は、記述だけで再現できる水準か。欠けているパラメータ、データ、手順はどれか。
4. 結果の解釈に、データが支持しない飛躍はないか。
5. 限界（limitations）は正直に書かれているか。書かれていない重大な限界は何か。
6. 図表は、本文を読まずに単体で理解できるか。キャプション、軸、凡例の不足はどれか。
7. 誤り（計算、引用、用語、表記）はどれか。
8. 査読者として、採択・条件付き採択・不採択のどれを推薦するか。その決め手は何か。

## 関心層・無垢・受信者の知識状態のヒント

- 関心層：分野に興味があり、一般向けの解説書を読む程度。専門用語・手法名・統計用語は「知らないこと」に。
- 無垢：論文の語彙（専門用語、手法名、略語、記号）をできるだけ列挙する。「要旨」「査読」といった学術の慣習も知らない。
- 受信者：査読者、指導教員、意思決定者、他分野の研究者など、論文が実際に届く相手を具体化する。読む目的（採否判定、予算判断、引用候補の探索）は状況に書いてよいが、作者の期待（採択されたい）は書かない。

## 判定の観点（シンセサイザーに渡す）

- 各ペルソナが「一番言いたいこと」として受け取った主張は、作者の意図した主張と一致したか。要旨だけで一致したか、本文を読んで変わったか
- 専門家が挙げた致命的な欠陥（主張と証拠の不一致、再現不能、重大な限界の欠落）はあるか。それは想定受信者の判断を変える水準か
- 想定受信者（査読者・意思決定者）が下した判断は、作者が期待する判断と一致したか
- 関心層・無垢に意義が伝わったか。伝わらなかった場合、要旨と序論のどこで止まったか

## 必要なツール

- Read（PDF、Markdown）
- `scripts/to-markdown.sh`（LaTeX、Word の変換。同梱の MarkItDown を使う）
