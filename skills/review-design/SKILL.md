# デザインのレビュー

## 受け付ける形式

- 画像ファイル（PNG、JPG、WebP）、複数可。ディレクトリ指定なら画像を名前順に並べる
- PDF（複数ページのカンプ）
- Figma の URL。**Figma の MCP は同梱していません。** 環境に Figma コネクタがあれば、それでフレームを画像として取得して `work/design/` に保存します。なければ作者に PNG 書き出しを依頼します

## 準備手順

1. 画像を `work/design/` に `01-`, `02-` のように順番付きでコピーする。画面遷移があるなら、作者に順序を確認する（順序は「操作の流れ」であり意図ではないので聞いてよい）。
2. 文字が小さい画像は、ペルソナが拡大できないことを前提に、そのままの解像度で渡す。読めなければ「読めない」という反応自体が結果になる。
3. 画像が1枚だけなら、その1枚を渡す。

## ペルソナに渡すアクセス手順（雛形）

```
1. 次の画像を順に開いて見てください：<絶対パスの一覧>
2. 画面を操作することはできません。見て感じたことを記録してください。
3. 複数枚ある場合、それは画面の流れです。実際に自分が操作している気持ちで、1枚ずつ見てください。
```

## 専門家の既定プロファイル

| 既定 | 代替（`--expert` で指定） |
| --- | --- |
| モバイルアプリと Web の UI/UX デザイナー（実務8年、デザインレビューを日常的に行う） | アクセシビリティ専門家、ブランドデザイナー、グラフィックデザイナー（印刷物の場合） |

### 専門家への具体的な問い

1. 各画面で最初に視線が行く要素はどれか。それは画面内で最も重要そうな要素と一致しているか。
2. 主要なアクション（ボタン等）はどれで、発見にどれだけ時間がかかったか。
3. 情報の階層（見出し・本文・補足）は視覚的に区別できているか。
4. 文字サイズとコントラストは、小さい画面や明るい屋外で読めるか。
5. 空の状態、エラー、読み込み中など、欠けている状態はないか。
6. 画面間で用語・配色・配置の一貫性は保たれているか。
7. 使われている用語で、利用者に通じなさそうなものはどれか。

## 関心層・無垢・受信者の知識状態のヒント

- 関心層：「アプリのデザインを見るのが好き」程度。「UI」「CTA」「ナビゲーション」「モーダル」「オンボーディング」は知らない語の候補。
- 無垢：画面の語彙（画面上のボタン名、機能名、略語）を「知らないこと」に列挙する。
- 受信者：実際にその画面を使う場面（端末、片手操作か、急いでいるか）を状況に書く。

## 判定の観点（シンセサイザーに渡す）

- 各ペルソナが最初に目に留めた要素は、作者が見せたい要素と一致したか
- 想定受信者は、主要なアクションに自力で到達したか。到達までに迷った画面はどれか
- 画面から受け取った印象（信頼できる、楽しそう、難しそう）は、作者の意図したトーンと一致したか
- 無垢ペルソナが読めなかった語・要素は、受信者にも通じないおそれがあるか

## 必要なツール

- 画像の閲覧：Read（同梱の MCP は不要）
- 任意：Figma コネクタ（環境にあれば画像取得に使う。同梱しない）
