# 発表用スライドのレビュー

## 受け付ける形式

- PPTX、PDF
- Keynote、Google スライドは PDF か PPTX に書き出したもの（Google スライドは環境のコネクタで取得してもよい。コネクタは同梱しない）
- 発表原稿やスピーカーノートがあれば、別ファイルとして受け取る

## 準備手順

1. `${CLAUDE_PLUGIN_ROOT}/scripts/to-markdown.sh <ファイル> work/slides/` を実行する。`content.md`（1枚ごとのテキスト）、`document.pdf`（PPTX の場合、LibreOffice があれば）、`pages/*.png`（pdftoppm があれば）が生成される。
2. **閲覧モードを決める。** 作者に確認する（これは意図ではなく配布形態なので聞いてよい）。
   - 配布資料モード（既定）：発表者なしで読まれる。ペルソナはスライドだけを読む。
   - 発表モード：発表者が話す。スピーカーノートがあれば、各スライドの下に「発表者の話す内容」として添える。ただし、ペルソナには「聞き手」として体験させ、スライドの文字を全部読む時間はないことを状況に書く。
3. ペルソナに渡すのは、見た目込みの `pages/*.png`（または `document.pdf`）を優先し、画像が作れなければ `content.md` を使う。

## ペルソナに渡すアクセス手順（雛形）

配布資料モード：

```
1. 次の画像を 1 枚目から順に見てください：<pages/ の絶対パス一覧>（または：次の PDF を 1 ページ目から順に読んでください：<絶対パス>）
2. 発表者はいません。資料だけが手元に届いた状況です。
3. 使える時間の目安を過ぎたら、途中でも回答に移ってください。
```

発表モード：

```
1. 次の画像を 1 枚目から順に見てください：<一覧>。各画像の後に「発表者の話す内容」があります。
2. あなたは会場で聞いています。1 枚あたり見られる時間は 30 秒から 1 分程度です。スライドの細かい文字を全部読む時間はありません。
3. 聞き終わった後、何を覚えているかが重要です。
```

## 専門家の既定プロファイル

| 既定 | 代替 |
| --- | --- |
| プレゼンテーション指導者（企業研修と学会発表の指導を10年）。加えて、題材分野の専門家を `--personas` で追加することを推奨 | 投資家（ピッチ資料の場合）、学会の座長（研究発表の場合）、経営企画（社内提案の場合） |

### 専門家への具体的な問い

1. 各スライドは 1 枚 1 メッセージになっているか。複数のメッセージを詰め込んだスライドはどれか。
2. スライドタイトルは「主張」になっているか、「話題名」にとどまっているか。
3. 文字量は、聞き手がその場で読み切れる量か。読み切れないスライドはどれか。
4. 図表は、説明なしで読み取れるか。軸、凡例、強調の不足はどこか。
5. 全体のストーリー（課題→提案→根拠→依頼）は一本の線になっているか。途切れる箇所はどこか。
6. 最後のスライドで、聞き手に何を頼んでいるかは明確か。
7. 用語・略語で、聞き手に通じなさそうなものはどれか。

## 関心層・無垢・受信者の知識状態のヒント

- 関心層：題材に興味がある聴衆。スライドに出る専門用語・略語を「知らないこと」に。
- 無垢：題材の語彙を列挙。グラフの読み方は一般常識の範囲で知っている。
- 受信者：実際の聴衆（上司、顧客、審査員、学会参加者）を具体化し、その人が会場にいる状況（何件目の発表か、関心の度合い、疲れ具合）を書く。発表者が期待する判断（承認、採択、投資）は書かない。

## 判定の観点（シンセサイザーに渡す）

- 各ペルソナが見終わった後に「一番言いたいこと」として覚えていたものは、作者の意図と一致したか
- 想定受信者は、最後に何を頼まれたかを言えたか。その依頼に対して取ると答えた判断は、作者の期待と一致したか
- 途中で離脱・集中が切れたスライドは、ペルソナ間で一致したか
- 専門家が「詰め込みすぎ」と指摘したスライドは、無垢・受信者の「わからなかった」と一致したか

## 必要なツール

- `scripts/to-markdown.sh`（同梱の MarkItDown、LibreOffice と pdftoppm があれば画像化）
- Read（画像、PDF）
